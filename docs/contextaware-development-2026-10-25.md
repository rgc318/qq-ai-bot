# ContextAware 第一阶段开发与验证

日期：2026-10-25（北京时间）。实施依据：[最终迁移方案](contextaware-selection-and-migration-plan-2026-10-25.md)。

## 结论

**三个接缝可以通过独立适配层接通，值得继续采用候选路线。当前交付是可复现的隔离候选与切换控制器，未切换正式 QQ 服务。** 无需重写 ContextAware 的 ImageIndex/SessionManager，也没有修改 AstrBot 核心或万象画卷源码。

人格/成员隔离、事实型场景、多图导出和万象画卷公开方法的权限/额度路径已验证。新增逐图用途参数，让模型说明如何使用自己选定的资料，不通过“三视图必须取两张”之类的生产规则替它决定。

## 已完成

- 固定并验证上游提交与文件散列，保留 MIT 许可。新增代码在 `integrations/contextaware/`，生产扩展 1.8.0 的文件和配置未改动。
- 根据现有 `attachment_identity` 返回的群/成员＋人格范围创建内部事件视图。原事件的 QQ 路由不变；内部会话键查模型/配置时映射回真实路由。
- 用独立呈现器替换规则行为指导，向模型提供带原消息 ID、发言者、时间、@ 和回复关系的事实。
- 模型通过原生看图工具回看真实像素，显式给出参考 ID 与用途。缺参、越界、重复、用途不对应时在图片生成前停止。
- 使用万象画卷 `generate_images_for_plugin`，`record_usage=True`，不开放任意本地路径；仅成功发送后登记结果；同一任务重入不重复生成或发送。
- 从现有 SQLite 附件档案冷恢复原图和生成结果，不增建第二套持久索引；校验作用域、完整性、过期和重置代次，恢复原消息来源及父图关系。
- 实现独立互斥控制器：空闲切换、请求代次固定、切换期间排队、失败回退和回退失败停止分发。尚未接到生产钩子与 UI。

## 验证证据

使用与现网相同镜像，独立容器禁网、只读、无生产数据卷/密钥。图片生成器和 QQ 发送器为替身。

| 检查 | 结果 |
| --- | --- |
| 原生接缝、素材、冷恢复与权限检查 | 45 项通过 |
| 后端互斥、请求租约、队列、取消与回退 | 9 项通过 |
| 真实模型合成测试 | 累计 30 次文本/视觉调用；DeepSeek 1017 与 Sol low；无真实生图、QQ 发送或群历史重放 |
| 纯文字本地准备 | 40 次；一组记录 p50 0.249ms、p95 0.385ms |
| 两张图冷恢复 | 同组记录 2.368ms |

上述时延测于隔离容器临时文件系统，只覆盖候选准备过程；不能代替生产数据卷、完整业务链或上游模型耗时。没有给正常文字路径新增串行摘要、识图或固定等待窗口。复杂历史看图本身需要工具往返和视觉模型调用，其时间不能算作零。

原生验证覆盖了权限包装后的最终 Provider 工具 schema：`reference_ids` 与用途字段仍存在；原生 runner 真正把两张视觉图交给模型，并把完整原图字节交给图片入口。

## 模型自主选择与评分修正

依次进行了三组有限合成测试，每组 10 次调用，没有无限重试：

1. 无生成结果干扰时，两模型都能保留原始正面＋新侧面，加入第三位成员素材，并在独立新任务中使用空参考集合。
2. 加入旧生成结果后，Sol 在继续修改时选择了三张图。原来的自动评分要求“恰好两张”，因此该项未通过；这并不等于漏读旧原图。
3. 增加通用逐图用途字段后，两模型均保留两张原始参考，并把旧生成结果声明为编辑底稿，明确忽略其错误侧面。原“恰好两张”的评分仍判这两项失败，但人工检查用途后，不能据此认定模型选错。

保留原失败报告，不覆盖成“全部通过”。后续评分已改为分别报告必要来源覆盖、最小集合匹配和额外素材用途复核；**选择了编辑底稿不是自动错误，漏掉必要原图仍是错误**。这是验收口径修正，不是在生产添加“凡三视图都带上旧结果”的规则。现有 30 次调用不构成两个模型可靠率的统计结论。

色块测试只验证来源关联、真实像素与工具协议。它不能证明生成模型会正确保持角色身份、正侧面结构，也不能证明全部群聊语义都已通过。现有实际群聊的问题尚未通过本次候选上线修复。

## 采用前尚缺的部署工作

1. 将收到的消息、成功发送结果和清理信号接到一个持续归档入口；目前只完成冷恢复适配，不能启用两套生成登记/自动选图器。
2. 管理完整的 AstrBot 插件钩子和工具生命周期，验证停用候选时其自身钩子确实不运行；将控制器接到后台单选开关。当前候选保持不可选。
3. 按最终方案接入通用历史分页浏览、唯一关注判断、多话题关联与长工具调度；这些没有因引入 ContextAware 自动完成。
4. 补具有真实几何/角色结构的合成素材、多人文字话题、歧义与沉默等验收，再进行测试群灰度。未授权真实资料重放，不能拿用户照片代替合成样例。

生产仍为 AstrBot 4.29.1＋本地扩展 1.8.0，正式 QQ 运行链路和模型未更改。因此本次开发没有增加现网回复时延，也不应把候选阶段的结果宣称为现网已生效。

代码入口及运行方式见[候选说明](../integrations/contextaware/README.md)。

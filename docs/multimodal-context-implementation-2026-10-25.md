# 消息与附件上下文：1.8.0 使用与验收

2026-10-25，已在现有 Docker Compose 部署启用，仅对测试群 `347440128` 生效。沿用原有模型、人格、推理参数、权限、接话判断和万象画卷；不叠加新的群聊插件。设计依据见 [研究方案](multimodal-context-plan-2026-10-25.md)。

## 现在的行为

- 允许范围内的图片消息即使没有触发 AI，也会登记消息 ID、发言者、顺序和附件 ID，并保存受控副本。多条独立上传分别保留，不再只有一个“最后上传”槽位。
- 同一成员 180 秒内只有一张明确相关的新图时，后续“给他换西装”等请求直接取得这张图。180 秒是自动附图窗口，不是素材保留时间。
- 多图、多人或较早指代，由主模型根据带来源的目录选择；必要时用 `read_group_message` 查原消息、`view_context_images` 读取真正的视觉输入。目录本身不是图片内容；歧义不能确认时应澄清。
- 当前附件/明确引用优先。独立新图要求明确的 `reference_ids=[]`；改图选择完整图片 ID 集合。漏参、缺图、跨范围或校验失败时停止该次图片调用，不静默换成旧图或无参考生成。
- 看图预览和万象画卷的原素材用相同附件 ID 关联。预览可缩放，执行前冻结原图副本；日志的源哈希可核对来源，不要求预览字节与原图一致。
- 万象画卷发送成功后登记生成图片与父图关系。若原生发送没有返回 QQ 消息 ID，只记明确的本地发送回执；不伪造 QQ ID。晚完成的旧任务不变成最新发起的请求。
- 按群/成员策略及人格隔离；接受到原有清理会话信号后旧授权失效。在途请求只看到进入时的消息边界，之后的新图不能混进该次执行。

可以先单独发一张图，再说“@大肥鱼 给照片里的人换上西装”。两图混合参考、引用另一成员图片时，应说明两张图分别负责什么；需要时直接引用目标消息。模型仍可能理解失误，这些机制提供真实输入、来源选择与失败保护，并不保证语义判断永不出错。

## 文件读取

首批支持 TXT/MD、文字型 PDF、DOCX、CSV/XLSX，在容器本地解析，不默认增加向量或摘要模型调用。工具 `read_context_document` 可按关键词和片段偏移查询，PDF 可指定 `page_or_range=2-4`。结果保留页码、段落/表格行、工作表/单元格位置。

初始限制：单文件 20 MB，最多提取 20 万字符；PDF 首批最多 200 页；表格最多 20 个工作表、每表 1 万行和 100 列。公式不执行，文档内嵌图片不自动识别。解析在有超时与资源上限的子进程运行，提取结果按内容哈希缓存。

扫描 PDF 明确返回需要 OCR，暂未开启 OCR、文档页图或音视频解析。文件须由 OneBot 适配器上报为 `File` 消息或消息引用；只上传群文件但没有对应消息的通知，当前不保证采集。

## 开关与保存期

入口：AstrBot → 插件 → **QQ 人格模型与回复条件** → 配置 → **统一消息与附件上下文**。

| 设置 | 当前值 / 作用 |
| --- | --- |
| `enabled` | 开启；关闭后停止新登记和扩展工具，恢复 1.7.3 短期承接路径 |
| `auto_attach` / `auto_attach_seconds` | 开启 / 180 秒；近期唯一相关图片直接附加 |
| `on_demand_read` | 开启；允许模型按需调用消息回看、历史看图与文档工具 |
| `documents` | 开启；可单独关闭文档解析 |
| 消息索引 | 每策略/人格范围最多 5000 条或 7 天 |
| 原素材副本 | 默认 24 小时，每范围 128 MB、总计 512 MB；达到容量可提前淘汰 |
| 执行素材副本 | 独立保存最多 24 小时，同样有每范围 128 MB / 总计 512 MB 容量限制，满额拒绝新任务 |
| 文档提取缓存 | 最多 64 MB / 24 小时 |
| 本轮目录 | 最近约 20 项，目录字符预算 1800；更早条目按需查消息 |

关闭扩展不会删除真实聊天历史，已有副本仍定期清理。新索引从启用后的消息开始建立，不会把已经丢失的旧附件自动恢复；旧图仍可通过有效 QQ 引用重新登记。旧文字检索、长期记忆的保留策略不变。

## 时延与日志

普通文字登记和目录构建仅访问本地数据，不新增模型调用；不对每张群图自动生成描述。简单承接可直接走原有一次主模型请求。复杂回看通常多出“主模型选工具 → 本地读取 → 主模型继续”的往返，应计入模型等待。

同一 Docker 数据卷上的 40 条合成文字测试，登记 p95 约 6 ms，额外目录构建 p95 约 2 ms；这是新增层的隔离准备耗时，不是 QQ 端到端回复或所有负载下的保证。图片视觉输入、远端下载、文档首次解析与模型往返仍可能增加时间。

新增来源日志记录登记、目录准备、读取、缓存命中、冻结参考和成功发送登记；只记录 trace、来源 ID、数量、哈希、状态与耗时。对核心日志中本扩展的 `read_group_message` / `read_context_document` 工具结果省略正文，实际模型输入保留；不改变其他工具日志。原有 QQ 原文和模型回复日志仍由 AstrBot 原设置决定。

已认证状态接口：`/api/plug/qq_persona_models/attachments/status`，仅返回计数和设置，不提供正文、下载 URL 或凭据。

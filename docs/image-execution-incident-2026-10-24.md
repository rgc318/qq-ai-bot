# 只说开工而未启动图片任务

2026-10-24，本地插件 1.4.1。

## 现场证据

16:24:34 用户引用图片并 @ 机器人，要求“把这个转换成人形”。本地准备约 0.21 秒，接话走 native_wake，未调用 Qwen 判断；LivingMemory 自动检索跳过，旧对话处理约 0.0012 秒。

原生 provider_stats 记录本次模型为 `qq-dragon-sol-low` / `cliproxyapi/gpt-6.1-sol`，开始 16:24:34.390，结束 16:25:28.558，耗时 54.168 秒。输入 9288 tokens、输出 304 tokens；正式对话最终仅 user / assistant 两条，用户消息含一张图片，没有 tool_calls。日志在普通文字“我来把它拟成人形……”后结束，没有 generate_image 或万象画卷节点开始/失败记录。

因此，长等待发生在主模型请求阶段，但后面没有出图的原因是根本未创建图片任务，而不是图片生成仍在排队。仅凭现有记录不能细分模型阶段的排队、读图、推理或接口重试各占多少。

## 调整

当本轮提供图片工具时，补充明确执行约束：实际创作或修改必须在该轮调用 generate_image / generate_selfie；引用图片后的拟人化、角色替换、风格转换也属于改图，不要求用户再补“生成图片”字样。不能仅输出开工承诺后结束，因为普通文字回复不会在后台自动续做。

模型仍自行生成图片描述和人格对白，pending_message 随工具参数一同返回，程序先发送提示再执行工具。不强制所有图片相关讨论都画图，也不绕过缺失参考图保护、人格工具权限或现成图库表情策略。执行约束独立于开工提示开关。没有增加一轮固定模型调用，没有自动重放现场请求。

这属于提示词约束的补强，不是对模型永不漏调工具的保证；当前没有新增自动强制生图或后台补做机制。

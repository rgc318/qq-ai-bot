# 按需找回旧对话

2026-10-23，本地插件升级到 1.3.0，已在群 347440128 启用。当前模型仍使用最近 12 个用户轮次；更早的文字可按需检索，不必每轮发送完整历史。

## 使用

正常追问即可，模型会结合近期上下文和旧话题线索决定是否查询。需要准确旧内容时，可以这样问：

```text
@大肥鱼 查一下之前聊过的活动安排，集合地点到底在哪里？按旧对话原文告诉我。
@大肥鱼 我们上次讨论的模型配置是什么？找一下旧记录，不确定的部分请说明。
@大肥鱼 查一下长期记忆，我之前说过喜欢喝什么？
```

前两类具体原话、代码、参数、约定可调用 `search_chat_history`；返回片段不足时，调用 `read_chat_history` 分页读取。长期偏好和提炼事实仍通过 LivingMemory 的 `recall_long_term_memory`，需要已保存的来源时可指定 `include_source=true`。这些是模型工具，无需手工输入工具名或固定指令。

## 保存范围与隔离

- 请求裁剪前，将已有上下文中的用户与助手文字建立本地索引；回复发送后再次保存当轮文字，减少切换新会话前丢失最后一轮的可能。
- 已核验归属的旧 gzip 归档和当前人格会话已回填。部署时有 41 条文字记录、8 个归档来源；重叠记录去重，后续聊天会继续增加。
- 沿用 UserPolicy 的机器人实例、群/成员策略及人格范围。公开群会话由同群成员共享；成员专属范围、其他群、其他人格、其他机器人实例不能互读。私聊、禁止访问和禁用隔离的会话不开放此功能。
- 开新会话、清空近期上下文不会自动删除检索索引；切换人格后使用该人格自己的范围。未能核验归属的旧归档跳过，不会按人格同名猜测归属。
- 仅检索实际保存过的文字，不会主动拉取 QQ 的全部历史。系统提示、工具载荷、图片原始数据不进入文字索引；旧图仍需引用或重发。

## 延迟与能力边界

每次请求附带最多 500 字符的旧话题摘录，取自用户侧文字。它是检索线索，不是完整的模型摘要；不会为每轮对话额外调用总结模型或向量接口。模型当前上下文足够时直接回答。

真实主模型诊断使用隔离临时索引、全新会话和随机测试约定：

| 场景 | 结果 |
| --- | --- |
| 查旧约定 | DeepSeek 主动调用搜索和原文读取，找回只存在旧记录中的地点与随机暗号；3 轮模型调用约 33.22 秒 |
| 普通问候 | 1 轮模型调用、0 次历史工具调用，约 5.62 秒 |
| 本地索引准备 | 两次分别约 5.2 和 6.8 毫秒 |
| 隔离检查 | 跨群、人格、机器人实例、成员专属范围与访问限制通过 |

以上不是固定速度承诺。需要搜索、阅读再作答时仍会多走模型轮次；普通聊天没有固定增加一次模型判断。搜索采用本地关键词索引，可能漏掉同义表达，模型可以换词或结合长期记忆；检索不到应明确说明，不能保证每次都自动想起旧信息。

测试不向 QQ 发送消息、不向生产索引或长期记忆写入合成事实。11 项本地索引测试、原生模型检索/普通闲聊诊断及 12 项已有回复回调检查通过。

## 配置、数据与回退

后台：**插件 → QQ 人格模型与回复条件 → 配置 → 旧对话检索开关与话题摘录 → 启用旧对话检索**。保存配置后生效，不需要重启 QQ；旧页面可刷新后查看新名称。

- `history_recall.enabled=true`：启用索引、话题摘录及原文检索。当前保持开启；体验中觉得不需要或等待变长时，可随时关闭，需要时再开。
- 改为 `false` 保存后停止新索引和历史读取，不附带旧话题提示，也不向本轮模型提供两项历史检索工具。已保存记录保留，再次开启可继续使用。
- 此开关仅控制新增的旧对话检索；近期 12 轮上下文、LivingMemory 长期记忆、人格模型、表情与生图保持原设置。上下文裁剪原有的 gzip 备份仍独立保留。
- `history_recall.catalog_chars=500`：旧话题摘录字符上限，最大 800；设为 0 不附带话题摘录，检索工具仍可使用。
- 人格如果手工限制了工具，需要允许 `search_chat_history`、`read_chat_history`；长期记忆另需允许回忆工具。现有两个人格继承已启用工具，已确认工具注册成功。
- 新群仍需先开放原生访问白名单，并加入本地插件回复条件允许群；不能只靠检索开关开放其他群。LivingMemory 另有自己的记忆白名单。

索引位于 AstrBot 持久化卷：`/AstrBot/data/plugin_data/astrbot_plugin_qq_persona_models/chat_history.sqlite3`；原始 gzip 归档在同目录的 `history_archive/`。索引含群聊原文，按聊天记录保管；停用功能不等于删除数据，删除或恢复时应同时考虑索引、归档及 LivingMemory，并先备份。

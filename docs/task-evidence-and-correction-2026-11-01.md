# 1.13.0 资料可见状态与一次任务纠正

已部署到现有 AstrBot，保留 ContextAware 后端、两群权限、原人格和聊天模型绑定及近期预览预算。首次升级前备份位于容器 `/AstrBot/data/temp/architecture-20261101-215518`；空回复与计费修正前的增量备份为 `/AstrBot/data/temp/architecture-20261101-220359`。

## 图片和文字输入

近期事实和最多 4 张预览仍直接提供给主模型。较早图片提供来源目录，由模型按聊天关系选择 `view_context_images`，目录不足时先浏览/搜索原消息；文档按需读取。不增加专门的选图、摘要或审核模型。

目录增加可用状态；请求内另有 `provided_image_ids` 和 `catalog_only_image_ids`。前者表示初始视觉输入已提供，后者只是索引。读图返回完整图片集合后登记已读 ID；文档只有返回非空摘录才登记。目录存在、实际读取和理解正确是不同的事情。

同一原图按原始字节摘要去重，只提供一份像素，但保留每位成员和每条消息的来源 ID 别名。不同编码、裁剪不合并。与正式历史完全相同的用户文字，在近期事实中仅留 160 字摘录和完整文本仍在正式历史的标记；不做模糊匹配，不删除原档案。其他历史仍可能重合，不是彻底语义去重。

## 完成检查与一次纠正

仅在启用资料工具的原生、非流式 Agent 中生效。依赖图片/文件的回答与工具任务通过内部 `QQ_TASK_STATE` 标记声明资料 ID、实际工具和任务状态；普通闲聊无需标记。标记在原生 Agent 保存/发送最终回复前去除，保留其余富媒体。

本地检查以下可验证事实：

- 声明使用的图片是否已有初始预览或实际读取结果。
- 文档是否返回过内容摘录。
- 声明执行的工具是否确实返回，失败是否如实报告。
- 图片完成是否有发送确认，部分批次失败是否被误报为整批完成。
- 当前并无后台任务注册能力，不能把普通等待句当作已启动后台任务。

明确矛盾或损坏的内部标记出现时，先不发送该条回复，向同一个原生 Agent 加入临时证据反馈，最多纠正一次。模型自行补读、修正决定或澄清，继续遵守原人格、工具权限、原生步骤上限及图片失败预算。纠正时已有图片发送成功，则禁用再次生图。人格/范围改变、会话清空或取消时中止；再次矛盾则说明未完成并记录 `incomplete`。

工具本身失败仍沿用原生续答和已有失败预算，不因出现错误就固定加审核轮次。模型声明的 `task_status/evidence_status` 与实际文字发送状态分别保存，发了一句回复不代表图片任务完成。

**已知边界**：模型完全漏报内部状态时，记录 `not_declared/unreported`，不通过关键词或额外审核模型强行推断任务。模型可能漏列依赖或理解错误，程序不能证明语义正确，也不能检出所有漏做任务。文件已读只代表获得摘录。流式请求暂不注入本协议，避免内部标记随流输出。

## 设置与日志

AstrBot → 插件 → QQ 人格模型与回复条件 → 配置 → **资料可见状态与任务完成检查**：`task_completion.enabled`。关闭后撤去完成协议和纠正，保留近期直传、目录、原图编辑、原有权限及失败预算。

近期预览仍由 `multimodal_context.auto_attach` 和 `recent_input` 控制。减少预览可能减少输入，也可能增加必要的工具轮次，不能承诺关闭就更快。

`task_evidence_check` 展示 `validation_code`、`task_status`、`repair_attempts`。其中 `correction_started` 表示启动一次纠正，`correction_exhausted` 表示未完成，`correction_aborted` 表示范围变化/取消。实际模型请求仍有 Provider、模型和耗时记录。补齐原先被白名单遗漏的初始图片数、预览字节、读取数量、来源 ID 和去重计数，不输出正文、图片地址、像素或凭据。

后端状态接口 `task_completion` 显示开关、适配器安装情况、非流式模式和一次纠正上限。

## 验收及耗时

211 项禁网原生运行检查、27 项架构检查、15 项新证据单元测试、56 项路由、24 项存储、4 项历史裁剪以及 Linux 日志回归通过。覆盖资料交付、多人来源、图片/文字去重、补读路径、部分交付、一次纠正、步骤预算、人格变化中止、私有标记移除、空回复、纠正调用的计费与上下文占用分离、原图执行与发送边界及适配器恢复。原生执行测试使用合成 Provider/HTTP，不向 QQ 发测试消息，不执行真实生图。

包含协议组装的最终 40 样本合成本地准备：ContextAware p50 7.114 ms、p95 8.582 ms，首次 42.747 ms；本地后端 p95 9.900 ms。此前另一轮 ContextAware p95 15.216 ms、首次181.445 ms，说明存在运行波动。这不是线上 p95，也不是受控的重构前后速度证明。

DeepSeek 1017 实际接口合成测试：

| 场景 | 请求次数 | 耗时 | 结果 |
| --- | --- | --- | --- |
| 同一预览，无完成协议 | 1 | 3.348 秒 | 正确回答颜色 |
| 有预览和完成协议 | 1 | 1.630 秒 | 正确回答，声明正确来源，无读图调用 |
| 只有目录 | 1 | 1.696 秒 | 选择正确图片 ID；诊断不执行工具 |

加入协议后，同一预览输入从 1157 增至 1437 token，输出从 59 增至 81 token。每种只有一个样本，不能把较短时间解释为协议提升了推理速度。正常成功请求不增加独立模型轮次；纠正发生时会增加模型等待。复杂人物、多视图与真实多人连续对话仍需正常使用验证。

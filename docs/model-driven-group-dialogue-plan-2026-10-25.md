# 由模型决定的群聊理解与资料选择

日期：2026-10-25。用户目标：让模型结合群消息自主决定是否回应、回应哪些人和消息、读取哪些图片或文档、调用什么工具。状态：架构调整方案，尚未实施；本文件没有改变运行中的 1.8.0 配置。

现成组件优先的选型、适配边界、停止条件与验证步骤见 [ContextAware 选型及迁移方案](contextaware-selection-and-migration-plan-2026-10-25.md)。本文定义目标，不预设必须继续全量自研。

## 需要纠正的方向

不为三视图、换衣服或表情包逐个增加决定用户意图的分支。任务笔记可以帮助保留上下文，但应由模型创建、修改、关联或结束，不把素材固定在只能由最初发起者使用的封闭任务中，也不把最新消息视为天然覆盖旧要求。

当前代码已经保管允许范围内的消息和附件，提供按 ID 看图和读文档。但接话仍有语义前置规则，跟进主要依靠一个最近 AI 活动和一个图片活动；图片工具漏参时还能沿用当前附件。消息快照也没有形成可分页浏览、可跨话题引用的完整对话工作流。不能把已有缓存和明确双图传递测试视作已完成自主多话题群聊。

## 目标处理流程

1. **记录公共消息时间线。** 统一记录消息 ID、成员身份、顺序、引用关系、文字、附件 ID、AI 回复与执行结果。群内公开资料可按现有权限跨成员引用；私聊、跨群及独立人格/成员策略仍保持隔离。收到资料不等于应该回复，也不等于已读取其内容。
2. **模型决定是否关注和如何理解。** 给决策模型有来源的近期消息和当前活动概览；必要时交给主模型检查。模型可选择沉默、回应问候、请求澄清、继续既有讨论或开始新讨论。不再以必须匹配任务动词、关键词或唯一最近任务为前提。明确唤醒可以直接调度主模型，回应内容仍由模型决定。
3. **模型自主回看。** 提供按消息 ID、时间范围、成员、关键词及前后游标浏览消息的工具。近期目录只是入口，不能要求模型事先知道较早资料的关键词；允许向前翻阅，定位空文字图片消息或其他成员的公开资料。看图必须真正返回像素，文档返回带出处的摘录。
4. **模型选择行动及全部来源。** 模型明确选择答复的源消息、对象，以及执行工具需要的附件集合。图片角色或用途可用自由描述表达，不预设只有正面、侧面、衣服等类别。不因新上传而自动抛弃旧图，不因存在旧任务而自动全部沿用。没有必要执行工具时可以只聊天。
5. **程序校验执行约束。** 只检查权限、来源 ID 的可见性、素材可用性、参数是否完整、数量和资源上限、去重与执行状态。程序不替模型判断用户真正需要哪张图。漏填来源选择返回可修正的工具错误，不能默默替模型挑当前图。模型可以重新选择或向用户澄清。
6. **结果回到时间线。** 成功、失败、实际采用的资料和已发送消息均有来源关系，供下一轮理解；不把“说要做”当作已排队，不把未读取的图当成已看过，不把生成草稿自动当作用户确认的权威资料。

## 多人、多话题与并发

- 一群允许同时存在多个模型识别的讨论，不只保存一个全局最近任务。讨论关联可修改，不按一个成员永久锁定一个线程，也不把全群所有发言强行合成一个问题。
- 新成员的发言可以补充既有讨论、提出另一个需求或与群友聊天，由模型结合来源和前文判断。意见冲突时应澄清或明确区分版本，不因后说话就自动覆盖其他人的要求。
- 共同表达一个问题时可综合答复，独立问题可以分别回复，引用或 @ 应指向实际回应的成员与消息。记录明确来源，避免串用成员身份和个人经历。
- 调度器负责消息去重、短批次聚合、推理并发和结果有序写入，不代替语义判断。不能用整群必须静默十秒来保证合并，也不能每来一条消息无限启动新模型请求。
- 长工具任务应具备独立执行状态，等待生图时仍能处理新的文字互动。执行输入冻结；推理期间的新消息进入后续决策，不偷偷修改已经提交的生成参数。若新要求要改变在途任务，应说明实际状态，并由模型选择后续动作。
- 迁移时必须验证 AstrBot 同会话历史写入与运行器的行为，避免并发请求相互覆盖；不能只在插件中启动后台任务就宣称已完成并行会话支持。

## 任务笔记的用途

笔记是模型的可修改索引：记录讨论目标、已确认内容、未解决问题、有关消息和附件出处。它可以跨讨论引用允许的公开资料，不代替原消息和图片。角色、话题和意图不靠固定关键词分类；用户更正、不同成员的立场、未经确认的模型建议应区分来源。

如果 A 先发正面图、后来补侧面图，模型可以保留两图。如果 B 要加入另一成员早前图片的道具，模型可以查询并选入第三张。如果 B 另问一个代码问题，模型应建立独立讨论，不必加入图片任务。发现歧义可以澄清，不能为了完成预设任务强行解释用户。

## 时延取舍

沿用本地索引与缓存，不为每张图片先调用描述模型。可保留轻量关注模型，但它也必须依据真实近期消息，记录所依据的消息 ID，并明确区分不回应、资料不足与判断失败；不能用少数硬编码锚点否决所有其他讨论。

若采用主模型直接观察每个群聊批次，能减少判断与正文之间的信息断层，但会增加普通闲聊的主模型调用量。两种调度方式须用代表性场景对照后决定，不能承诺全部场景更快、更便宜或绝不误判。复杂历史回看和模型修正漏参都会产生必要的工具往返。

## 验收要求

用合成资料验证完整流程，而不是只在测试里人为选好正确图片：

- 原参考图 → 首版结果 → 补充第二视角 → 模型自行回看并选择所需资料。
- 加入其他成员早前的图片元素；明确替换旧图；明确另起角色；引用有歧义时澄清。
- 两名成员同时提不同问题；第三名成员补充其中一个问题；多人意见相反；无人向 AI 发问时沉默。
- 文本创作、代码讨论、信息问答、读文档和图片任务采用同一套资料选择原则。
- 生图等待期间回应另一位成员；迟到结果、人格切换、清理、权限隔离和重复消息。

检查最终序列化的模型输入、实际调用的工具与来源 ID、最后交给图片接口的参考集合以及消息发布对象。不能仅凭模型口头说已理解、缓存存在或手动填入正确参数就判定通过。不重放真实聊天/图片做外部诊断，不未经授权发群验收消息。

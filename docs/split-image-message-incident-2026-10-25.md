# 先发新图、再发文字却修改旧图

## 现场证据

2026-10-25 北京时间，测试群先单独发送一张照片，再向 AI 发送换西装的文字请求：

- 13:02:11，收到独立图片事件，消息 ID `1707898070`，作为普通群消息观察，未进入正文生成。
- 13:02:20，收到改图文字，消息 ID `2106864302`，trace `f747c1d3d141`。主模型请求的 `image_count=0`，说明这次正文调用没有收到新照片像素。
- 首次工具调用因缺少旧参考选择参数被拒，但旧兼容保护在实际工具对象上未生效，出现 `_qq_image_guard_error` 非预期参数错误。模型随后重试。
- 13:02:30，重试选择 `selected_previous_reference=true`，缓存参考数量 1，实际附加数量 1。此次使用了旧任务的参考图，生成了旧角色的西装版本。
- 后续 13:03:24 的另一条请求 `-1882902143` 已有 `image_count=1`，不能与前一条混为同次调用。

主要原因是图片消息未被正确承接到后续文本请求，不是已经把新照片传给模型后仍认成旧角色。现有图片缓存仅在 `on_llm_request` 中捕获，未触发 AI 的独立图片事件没有进入缓存；近期文本里即使有“图片”占位也不等于模型拿到了图像。增加聊天文本上限不能修复这类缺失。

## 1.7.3 修复

1. 允许群、策略范围与人格确认后，即便不触发 AI，也记录成员最近一次直接上传的图片及来源消息 ID。按成员保存，最多 16 名成员、每次最多 4 张；不把引用图误认成新上传。
2. 同一成员随后提出涉及图片或指代的文字请求时，默认 180 秒内可以附上新图像素。明确引用、当前附件优先；跨成员、跨人格、过期、新任务已覆盖、独立创作等情况不自动沿用。不是对每种自然语言指代的完备保证，歧义场景仍应引用原消息。
3. 收图时不新增判断/描述模型调用，也不为普通群图片下载文件。实际承接时优先使用已有本地文件，必要时通过原生图片接口读取，最多等待 4 秒；缓存文件用像素校验与受限数据目录保存。新图无法完整读取时关闭此次图片工具，不退回旧参考图。
4. 补修 `file://` 图片组件的缓存解析：优先读取真实 `path`，并识别本地文件 URI，避免程序恢复的图片明明可用却被缓存为零文件。
5. 执行保护在 `on_using_llm_tool` 接收到的实际工具对象上安装，支持原生 runner 送来的未包装 handler；生命周期结束可恢复。原生结束回调传回原始参数，不一定包含校验过程中增加的标记，因此也按受控的“画图未执行”结果保留旧任务状态。
6. 增加 `recent_upload_reference`、`image_source`、`source_message` 元数据日志，不记录图片像素、URL、正文或凭据。

后台本地插件“从上下文承接图片请求 → recent_upload_seconds”可调整窗口，0 关闭，最大 600 秒。没有改变主模型、图片模型、推理档位、重试或群权限。普通文字不新增调用；真正提供新图时，图片读取及模型处理视觉输入本身仍会耗时，不能承诺零影响。

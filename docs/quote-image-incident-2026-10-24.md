# 引用机器人原图读取失败

2026-10-24 09:20:47，用户引用机器人发出的“柴犬头顶蓝色水桶”图片，并要求“把这个换成真人”。本次入站消息 ID 为 -638647607，引用消息 ID 为 1393419635，群为 347440128。

## 已确认的原因

1. 引用链本身存在，发送者确为机器人 QQ 2354912009，包含一张图片。但 QQ `multimedia.nt.qq.com.cn` 下载地址返回 HTTP 400，原生预处理未能下载；主模型组装图片时只能得到不可用占位符。
2. 该轮上下文裁剪日志 `old_images_removed=0`，没有证据表明是本次历史检索或图片裁剪导致当前引用丢失。问题发生在 QQ 引用图下载环节。
3. 模型没有实际看到这张原图，却沿用了旧会话的“长发女子、蒸笼、猪脚饭”内容生成改图提示。万象画卷随后再次下载失败，仍以空参考图继续生成。
4. 上游对这份错误提示返回安全拒绝 `safety_violations=[sexual]`。这是另一次请求失败；不能将其解释为工具一律不支持真人或写实风格。

只读重现确认：`get_msg` 返回的原地址失败，`get_image` 没有给出有效远程地址。将同一 QQ 文件地址的 rkey 替换为当前群聊下载密钥后下载成功，得到 1,878,704 字节、1254×1254 的 PNG。本地万象画卷 `temp_images` 中也找到 MD5 完全一致的原图，非按时间猜测的“最近一张图”。

## 1.3.2 修复

- 在原生预处理的图片归一化位置安装可恢复的兼容层，发生在主模型读取图片之前。正常文字聊天不查文件或请求密钥。
- 只对当前允许群和插件权限允许的事件生效。机器人自己发出的引用图片，优先使用 QQ 图片文件标识中的 MD5，匹配万象画卷生成缓存；限定缓存目录、类型、大小和像素，不采用模型给出的路径，也不按旧任务描述选图。
- QQ 图片地址实际下载失败时，通过现有 OneBot 连接读取当前 rkey，只替换固定 HTTPS QQ 媒体域名上的下载参数，再走原生下载与格式校验。不会把下载密钥附加到其他域名；不绕过平台或插件的访问控制。
- 找回后，主模型和绘图工具使用同一张原图；本轮提示要求以实际引用图为准，不把旧任务描述当作当前画面。
- 引用图仍不可用时，本轮不提供生图/自拍工具，明确提示原图读取失败；万象画卷允许群的生成入口也增加完整参考图检查。单图或多图中任何参考图读取失败都会停止此次改图，避免静默变成无参考生图。
- 补丁在插件卸载/重载时恢复原方法。没有改写 AstrBot、SnowLuma 或万象画卷的安装源码，没有重启 QQ，也没有修改上游安全设置。

## 验证

- 实际引用消息经过原生 OneBot 解析与图片预处理后，从本地缓存恢复原图，首次约 0.0596 秒。MD5 与 QQ 引用标识完全相同，万象画卷提取并验证的也是同一路径。
- 当前 DeepSeek 1017 实际视觉调用描述为“一只闭眼微笑的柴犬头顶着一个倒置漏水的蓝色透明饮水机水桶”，主体与主要物体正确。
- 11 项兼容测试通过：精确缓存命中、密钥刷新、恢复失败保护、其他发送者不冒用本机生成缓存、单图/部分参考失败阻断、正常生成保留、作用范围、域名限制、模型不能指定路径，以及缺图时移除绘图工具。
- 既有 10 项双参考图与模型开工提示兼容检查、5 项 GIF 上传检查通过；人格绑定、旧对话开关及运行时补丁装载均通过回查。

上述验证没有向 QQ 发消息，没有请求新的图片生成，也没有把测试回复保存进生产对话或长期记忆。没有重新请求被上游拒绝的提示词。用户可在 QQ 中重新引用同一张图验收实际回复及改图效果。

## 边界与维护

本地生成缓存可能被正常清理，届时会走 QQ 下载及密钥刷新；若原消息或远程原图已经不可取回，仍需重新发送。对普通群友图片不使用“机器人自发原图”缓存匹配，但可以在 QQ 下载失败时刷新密钥。此修复不意味着任意旧图都永久保存，也不能保证上游允许每一种绘图请求。

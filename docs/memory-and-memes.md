群聊公开消息可作为该群记忆背景；长期记忆会逐步整理，不是每条消息都立即变成一条记忆。旧 QQ 聊天没有自动批量导入。重要偏好可以明确要求记住，并以工具实际成功结果为准。

性能优化后不再对每一句闲聊执行向量查询。自动整理与保存仍启用，模型在确实依赖以往事实/偏好/约定或收到明确回忆请求时使用 `recall_long_term_memory`。这会减少固定等待，但模型也可能没有主动回忆；重要的旧约定可以直接问“查一下长期记忆，我之前说过……”。本地请求规则会提示模型按需检索，实验自主回忆仍关闭。配置和测量见 `performance-optimization-2026-10-23.md`。

1.3.0 另增加了本地旧对话原文检索：具体原话、代码和参数可查已保存的文字记录，长期提炼事实仍由 LivingMemory 管理。两者按需使用，不对每轮闲聊执行两次查询。范围、跨新会话行为与配置见 [按需找回旧对话](history-recall.md)。

## 怎么使用

```text
@机器人 记住：我喜欢乌龙茶，不喜欢咖啡。以后推荐饮品时参考这个偏好。
@机器人 我之前说过喜欢喝什么？
@机器人 来个开心的表情。
```

平时正常聊天即可，模型按语境选择是否配图。大肥鱼与龙娘使用各自的长期记忆；切换人格后，另一人格不会自动读取前一个人格的偏好。若希望两个人格共享记忆，需要另行调整隔离规则。

2026-10-23 已修复“发个表情包”被误当作新图创作的问题。本地插件 1.2.1 对明确的现成表情请求在当前请求中移除生图、自拍、视频工具，并要求按图库分类协议选图；明确“画/生成/制作/改成”新表情时仍保留创作能力。12 个意图案例及真实模型验证通过，测试中约 2.69 秒准备一张图库图片，未向 QQ 发送测试消息。实际响应仍受模型和网络耗时影响。记录见 `logs/existing-meme-request-verification.json`。

人格切换仍在“多人格管理 → 群聊管理”操作，或由支持的群主/管理员使用 `/群切换人格 ChatGPT龙娘`、`/群切换人格 大肥鱼`。切换后本地插件 1.2.0 同步传递本次有效人格，Meme Manager 按其原生规则选择表情包，聊天模型绑定保持不变。

## 后台入口

打开 http://127.0.0.1:6185/ 。

- **记忆模型**：插件 → LivingMemory → 配置，修改 Embedding / LLM Provider。
- **查看、编辑记忆与召回调试**：插件 → LivingMemory → Pages → dashboard。
- **记忆白名单、整理轮次、隔离、备份**：LivingMemory dashboard → 设置。
- **上传/替换/安装更多表情**：插件 → 表情包管理器 → Pages → 管理页面。
- **给人格指定表情包**：表情包管理器 → 设置中心 → 使用规则，修改“人格”规则；管理页选中的包只控制浏览，不等于聊天实际选包。
- **每条表情上限、配图提示、自动收集**：表情包管理器 → 设置中心，或原生插件配置。

新增群时，除原生群白名单、人格规则、两条自动回复白名单外，还要检查 LivingMemory 的记忆白名单。表情包规则按人格设置，当前仅有测试群获原生访问许可；开放新群后需按该群需求调整选包与插件权限。

## 新旧表情隔离的兼容说明

多人格管理 3.5.6 的旧表情隔离适配器寻找 `MEMES_DIR/MEMES_DATA_PATH`，新版 Meme Manager 5.2.5 已改为原生多包规则，旧接口不存在。旧开关在该社区版本中被强制规范为启用，因此兼容页可能仍显示旧适配器未生效。

## 持久化与维护

插件、配置、记忆数据库、索引和图库位于 `qq-ai-bot_astrbot-data` 卷内。保持正常容器重建时挂载此卷；不要执行 `down -v`。社区插件会检查并安装声明的 Python 依赖，首次启动或重建后的依赖安装可能需要网络和时间。

更换 Embedding 模型或维度后，需要按 LivingMemory 文档重建索引，不能只改名称继续沿用旧向量。备份、召回调试和记忆修改可以在 dashboard 完成。当前管理员仍是机器人自己，后台管理可用，管理员专属群指令需先配置真实操作者 QQ。

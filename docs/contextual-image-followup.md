# 图片请求的上下文承接

2026-10-24，本地插件 1.6.0。

“把这个转换成人形”之后再说“图呢”，应该结合原请求、助手回复和工具执行事实理解，不能一律要求用户重发完整指令或重新上传图片。此前系统只保留最近一次 AI 活动，普通问候会覆盖它；文字回复已发送也没有表示图片工具是否真正执行。Qwen 超时时又会直接静默，导致主模型没有机会理解前文。

## 当前处理

独立保留当前群/成员策略及人格范围内最近一次带图会话，以及真正调用过图片工具的会话事实：原请求者、原要求、原回复、参考图数量、工具调用次数和观察到的状态。普通问候不覆盖这份记录。它不是所有任务的完整待办系统，也不是群聊完整历史的替代品。

| 状态 | 事实含义 |
| --- | --- |
| not_called | 没看到图片工具被调用；普通看图问答也可能如此，不能自动认定欠图 |
| running | 已收到工具开始回调，尚未收到结束结果；不代表本机已确认远端推理进度 |
| sent | 图片工具明确报告成功下发至少一张；不等于已验证每个客户端显示成功 |
| failed | 工具明确返回错误 |
| result_unconfirmed | 结果不足以确认成功或失败，例如报告下发 0 张 |
| interrupted | 从持久记录恢复了此前 running 状态，不能假定原任务还在运行 |

主模型结合当前发言、多条近期消息、原请求与这些事实决定怎么回应。实际催办/续做且此前未执行，可以调用工具；普通问候按人格回应，不因为存在旧任务自动画图；正在处理时不重复启动同一任务。问候、任务续接和新创作的示例通过提示词帮助理解，不是把“图呢”写成固定字面触发器。

接话判断同时得到独立的近期图片会话资料，能在最近普通回复已经变成问候时仍指向原任务。语义判断明确否决、明确指向其他人、其他成员或范围不匹配，不因判断失败而强行借用旧任务。只有同一原请求者、有效窗口内且没有明确人类对话交接时，判断调用失败/退避可转主模型核对上下文。日志 reason 为 `context_review_judge_unavailable` / `context_review_judge_backoff`，recipient 为 context_review，不能把它当作已经得到肯定判断。

直接 @ 绕过 Qwen，但主模型也会获得简短图片会话事实。它若决定续做旧图，工具参数 `use_previous_reference=true` 让程序恢复同一范围的原图；新创作可选 false。这是请求副本的参数，在调用图片后端前移除。若存在旧图选择但模型漏填，不静默退回无参考生成。已匹配的语义续接会直接提供恢复的参考图。

## 原图、范围与保存

优先保留原始字节的受控缓存，避免原生临时文件清理后无法接续。首次恢复时，也可读取匹配当前策略绑定和人格的原生会话，将其中的图片 data URL 校验后还原；不从聊天文本随意解析本地路径，不借用绑定缺失时的默认共享会话。

最多保留 4 张参考图，单张最多 20 MB、2500 万像素；支持 PNG/JPEG/WebP/GIF。恢复不改像素，GIF 上传兼容仍由原有适配器负责。参考图缺失、只恢复了部分或作用域不匹配时停止改图，不能悄悄无参考生成。只有真正无法恢复时，才需要用户补图。

事实写入本地插件的 reply_context.json，图片在其数据目录 reply_media/。缓存只按自身 SHA256 文件名管理，过期清理至少保留一天且比关联窗口长一小时，不删除其他命名文件。切换人格或成员策略时，旧记录不能跨范围附带；重载后原 running 记录转为待确认的 interrupted。

## 配置与时延

后台：插件 → QQ 人格模型与回复条件 → **从上下文承接图片请求**。

```json
{"contextual_image_followup":{"enabled":true,"window_seconds":86400,"fallback_to_main":true}}
```

当前保留最近一次图片会话 24 小时。关闭 enabled 停止这份图片上下文承接；关闭 fallback_to_main 只关闭判断失败时的主模型回退，正常语义判断及直接 @ 仍可用。

没有新增固定静默或每次再跑一次意图模型。带有旧图片事实的请求会增加少量输入；需要读图/改图时恢复原图，会产生相应视觉输入。更长的图片关联也可能让原请求者的后续消息进入语义判断；其他成员仍需要近期对话、点名或请求线索，不据旧图片一律唤醒。判断超时后主模型回退本身有额外调用耗时，这条路径以前是直接不回复，不能把它描述成完全零时延成本。

此功能不会在部署后自动重放已经消费的 QQ 事件，也不会因为历史里有未完成事项就自行在后台补图；需要一个新的互动事件，再由模型判断当前是否在承接。模型对状态的措辞仍可能不严谨，应以工具调用和下发日志为准，不保证所有上下文都零误判。

- 原有 37 项路由规则、12 项回复回调、13 项多人上下文检查及历史/记忆/模型绑定检查通过。
- 模拟判断超时，真实龙娘面对“图呢”从生产会话的隔离副本恢复原要求与原参考图，返回 generate_image，图片执行器获得 1 张原图；主模型约 14.20 秒。超时为替身注入，没有故意等待生产 8 秒。
- 直接 @“图呢”返回工具调用，模型选择沿用旧参考图，实际执行前剥离辅助参数；约 11.48 秒。
- 真实 Qwen 与龙娘对“说好的那张怎么还没见到”也返回图片工具调用，Qwen 本次判为 semantic_addressed，主模型约 10.86 秒，仍恢复同一原图，说明不依赖固定“图呢”字面。
- 直接 @ `hello?` 只回应问候，不调用图片工具，约 4.91 秒。早期一次负例曾误补图，调整旧请求引用地位、当前意图和示例后复测通过，失败报告保留。

模型测试没有调用图片生成 API、没有发 QQ 消息，也没有保存合成回复到生产会话或长期记忆；图片执行和发送由捕获式替身拦截。原图恢复副本及临时测试状态位于隔离目录，测试结束清理。以上不是实际群内图片送达验收，也不能保证每次有相同耗时。

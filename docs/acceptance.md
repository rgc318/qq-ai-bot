# 部署验收

本页用于逐项验收，未勾选项表示尚未在统一清单下完整复核，并不表示从未测试。当前已验证范围见 [STATUS.md](../STATUS.md)；真实历史双图编辑与 QQ 投递见[流程记录](runtime-latency-review-2026-10-26.md)，禁网合成回归见 [1.14.0 整理](release-1.14.0-2026-11-03.md)。不要用服务健康、替身发送或接口探测替代真实 QQ 验收。

- [ ] SnowLuma 识别到预期的 QQ 账号。
- [ ] AstrBot OneBot v11 日志显示连接成功。
- [ ] 主人私聊可以收发普通文本。
- [ ] 测试群通过 @ 或指令触发，普通消息不重复触发。
- [ ] 未放行的账号、群无法使用机器人。
- [ ] 模型 API 测试成功，QQ 回复确实使用指定模型。
- [ ] 私聊和群聊的上下文按预定方式隔离。
- [ ] 引用消息可以正常处理。
- [ ] 若开启图片理解，图片能传到支持视觉输入的模型。
- [ ] 模型 API 超时或不可用时，机器人能恢复处理后续消息。
- [ ] 分别重启 AstrBot 和 SnowLuma 后能够重新连接，回复没有明显重复。
- [ ] 连续观察至少 24 小时，记录断线、异常和资源占用。

工具已经用于搜索、记忆和图片任务；每次增删工具或变更权限后另行验收：

- [ ] API 能返回有效工具调用。
- [ ] 仅启用预定插件或 MCP 工具，并核对权限和操作对象。
- [ ] 近期图片直接进入视觉正文输入；较早图片由模型按来源回看，改图工具取得对应原图而非错误历史图片。
- [ ] 不同群 / 成员 / 人格的资料范围不串用；多成员补充条件仍能理解，切换人格时在途任务归属正确。
- [ ] `first_segment_sent` 与全部 `sent` 分别计时，首段人工等待为 0、后续使用原生间隔。
- [ ] 图片失败和部分成功如实反馈，不把文字回复或工具调用开始当作图片已经送达。

遇到可复现的 SnowLuma 问题时，先保留版本、脱敏日志和复现步骤，再用 NapCat 做兼容性对照。切换时重新验证图片、引用和插件能力，不将 OneBot 兼容等同于所有扩展接口兼容。

# ContextAware 选型、复用与迁移方案

日期：2026-10-25（北京时间）。状态：完成源码与本机配置核对，等待隔离接入验证；没有安装 ContextAware、切换生产流程或执行真实群聊/图片重放。本方案承接[模型自主群聊目标](model-driven-group-dialogue-plan-2026-10-25.md)。

## 1. 推荐决策

**先用有明确边界的隔离验证评估 ContextAware，优先采用现成能力；通过准入条件后才迁移。若必须长期维护大范围分叉或两套上下文系统，选择继续现有扩展，并复用适合的社区模块。**

这不是先重写一套再比较，也不是先安装到生产后不断补丁。两条路线共用同一组场景、模型、权限和时延指标，只有一个上下文/选图入口成为运行时的负责人。无论选择哪条路线，都由模型决定意图、讨论关联和资料选择；程序负责权限、资源有效性与执行约束。

目前不能断言 ContextAware 整体更优，也没有证据认为现有自研更可靠。已确认的价值是它提供了现成的多图回看、GIF/视频预处理和图片交接接口；主要适配风险是人格/成员隔离、规则场景指导及万象画卷对接。

## 3. 复用范围与真实差距

| 需求 | ContextAware 已有能力 | 接入后仍需解决 |
| --- | --- | --- |
| 模型选择多张历史图、跨成员参考 | 图片目录、真实视觉回看、来源信息、版本化交接 API | 模型是否主动查全资料要用连续任务测试，不能手动选好 ID 后宣布成功 |
| 群聊场景 | 带来源的近期对话和发言对象提示 | 收件人包含规则推断，需确保不会冒充已确认事实或压过模型判断 |
| GIF、视频、图片压缩 | 有现成预处理和可配置能力 | 非当前验收重点的功能先关闭；视频/语音服务和工具依赖单独验收 |
| 当前话题保留 | 可选群聊摘要、私聊话题笔记 | 群内多人、多话题并行不是私聊笔记的等价功能 |
| 自主沉默 | 可配合已有社区沉默插件 | 触发、沉默和空答修复须衔接，不能把模型沉默误当接口异常 |
| 完整历史浏览与文档 | 主要是近期场景和短期图片目录 | 保留现有文字/文档索引，增加按时间和游标翻阅原消息的通用工具 |
| 生图与结果登记 | 当前文档联动 Gitee AI Image | 万象画卷仍需一层明确的接口桥接，不能假设安装后自动互通 |
| 多讨论与慢工具调度 | 有缓存并发保护、任务来源记录 | 仍须复用/扩展 AstrBot 和业镜调度，验证同会话历史写入及多人请求不丢失 |
| 重启与素材保留 | 当前图片索引为短期缓存，重启/重载会失效 | 不能把现有磁盘恢复与 24 小时保留悄悄降级；历史素材的恢复路径必须明确 |

**历史浏览、多讨论调度等缺口，两条路线都要补，不能把共同需求全部算作 ContextAware 的迁移成本。** 相反，人格隔离适配、重叠功能退出、缓存语义对齐是采用 ContextAware 额外产生的成本，应单独评估。

## 4. 路线 A：ContextAware 为近期上下文和图片组件

### 职责划分

| 职责 | 负责人 |
| --- | --- |
| 平台连接、现有模型调用与基础 Agent | SnowLuma、AstrBot |
| 人格、模型绑定、成员权限及记忆隔离 | User Policy 和保留的本地绑定部分 |
| 近期群聊观察、图片目录、按需视觉回看 | ContextAware |
| 群消息触发、合并与发送调度 | 优先复用业镜/原生运行器已存在的能力，再补缺口 |
| 生图、改图、自拍和原有模型配置 | 万象画卷 |
| 图片 ID 交接、发送成功登记、诊断 | 一个独立且可撤销的兼容层 |
| 旧文字、文档、长期记忆、表情包 | 现有索引、LivingMemory、表情包管理器 |

### 三个必须先验证的接缝

**A1：权限与命名空间。** ContextAware 主流程和图像 API 使用 event.unified_msg_origin，不能直接等同于 User Policy 的群/成员＋人格隔离。公共群消息可以按现有政策被其他成员理解；成员独立上下文、私聊、人格历史与未发布资料不能混入。测试必须覆盖不同成员策略、人格切换和清理。不得通过修改全局 event 的 UMO 来破坏平台路由，也不能以关闭隔离来省事。若需要窄会话键扩展，应保持真实平台身份与内部索引键分离。

**A2：模型保留最终判断。** 源码 infer_addressee 根据 @、回复、短确认和时间关系推断对象，SceneGenerator 再生成行为指导。strict_mode=false 只是取消额外强制，不等于关闭全部规则；enable_dialogue_flow=false 也不等于关闭收件人推断。当前未发现一个独立公开开关，能只停止规则场景指导而完整保留按需图片回看；enable=false 会使 _should_process 返回 false，不能冒称是“仅关闭场景但保留回看”。隔离验证应确认可否用一个窄扩展点输出事实和带置信标记的建议，让模型自行决定。如果必须重写场景系统才达标，停止整套接入。

**A3：万象画卷桥接。** 模型显式选择图片 ID，可选自由用途说明；通过 get_image_catalog / resolve_reference_images 验证来源，再冻结输入，调用万象画卷已经公开的插件接口或现有正常聊天入口。优先公开接口，不放宽任意本地目录访问、不绕过原权限和额度。仅在实际发送成功后调用 register_generated_image，失败不登记为成功。开工对白继续由本轮主模型提供。漏填来源选择应让模型修正或澄清，不默认替它选当前图片。

ContextAware 的图片交接 API 提供来源和 bytes，降低了桥接成本，但不能据此承诺无需修改即可运行。素材格式、自拍身份、计次、发送回执、异常、取消和迟到结果均需要替身验证。

### 素材所有权与重复功能退出

每个来源在同一请求中只暴露一个权威附件 ID；不得让两个插件分别判断最后一张图、分别附图、分别登记结果。活跃缓存和持久历史可以分层，但必须有基于原消息、位置与内容的明确映射，不能依赖模糊文字匹配。

先判断 ContextAware 能否通过小适配使用/恢复已有素材档案。若为了保留当前能力需要新写一整套图片归档、恢复和 ID 同步系统，且不能退役现有附件选择器，则认为采用整套插件收益不足，转路线 B。不要用同时保留两套选图器掩盖迁移失败。

通过验收后，依次退出本地近期重复快照、自动历史附图和旧选择回退；保留人格绑定、旧文字检索、文档读取、日志及必要权限适配。原生 group_icl_enable 以及 image_caption 等重复入口按职责关闭，操作前保存快照；LivingMemory 长期整理不因此关闭。现有规则不能一次删除导致无回复，须在隔离测试和单群灰度中逐步替换。

### 候选初始配置

以下为验证建议，不是已保存配置：

- 保留两个现有聊天模型与 image2.5 节点，不为插件迁移更换模型或协议。
- image_recall=true、image_recall_auto=false，让复杂选图由模型完成；当前明确附件仍按原生输入处理。
- image_recall_max_per_request=4；验证多张参考与高清升级计数，未读像素不当作已读。
- show_sender_id=true；image_caption=false、history_compress_strategy=off、private_topic.enabled=false，先避免额外总结与识图调用。
- strict_mode=false，但仍须处理 A2；不能用这一个开关宣称已经纯模型决策。
- 视频和额外语音转写先关闭；独立图片压缩先不叠加，GIF/高清能力待静态图片主链通过后启用。
- TTL、缓存大小与恢复策略须保留已约定的体验，不能只把短期 TTL 调长就宣称已实现重启恢复。
- 初期仅测试群；不得顺便扩大私聊或其他群的接入范围。

## 5. 两条路线共用的最小补充

**通用历史浏览。** 扩展现有 read_group_message，支持前后游标、时间段、成员和引用关系；文本/文档走现有存储，不为此再建第二套数据库。必须能定位只有图片、没有文字的旧消息，并返回可供后续读取的权威附件来源。

**模型决策和沉默。** 可以保留轻量关注模型控制费用，但它应根据真实近期消息判断，不用单一任务锚点或几条关键词否决其他话题。主模型可继续查资料、自然回应、澄清或沉默。优先评估作者推荐的[算了不说了](https://github.com/muyouzhi6/astrbot_plugin_suanle_bushuo)的现有 keep_silent 工具，不复制完整黑名单系统，也不自动安装。当前空答修复必须识别真实、成功的沉默工具结果，不能把接口空返回当作自主沉默，或把主动沉默不断重试成回复。

初始候选优先复用业镜已有的模型判断，逐步停用本地重复的 Qwen 判断与任务词门槛；必须核对业镜传入的触发标记和 ContextAware 的识别结果。保留一个关注判断入口，不让“本地判断 → 业镜再次判断 → 主模型”串行叠加。明确 @ 和已有唤醒按正常入口进入，最终如何回应由模型决定。若选择继续用本地关注器，也应关闭对应的业镜重复判断，而不是同时开启两套。

**多话题与执行调度。** 模型可关联多条源消息、跨成员补充或建立独立讨论，笔记可自由修改，不定义“三视图任务”等固定模板。优先检查原生追加消息机制与业镜已有队列，只有缺失部分才开发。短推理按消息快照调度；长工具任务独立记账；结果按所属请求写回，不能争抢一份可变的群历史。无需整群持续静默，明确唤醒也不新增统一等待窗口。具体并发实现要用实际 AstrBot 4.29.1 验证。

## 6. 路线 B：保留现有存储，改为模型自主调度

出现下一节的停止条件时，保留已经验证的消息/附件持久层、文档解析和万象画卷集成，不继续迁移整套 ContextAware。开发重点只放在通用历史浏览、多讨论上下文和模型明确选择资料，退出按场景追加的语义分支。

GIF 抽帧、图片预览、压缩等能力优先使用锁定版本的可复用模块，先评估依赖边界并保留 MIT 许可；不复制 ContextAware 整个 main.py 后再改名维护。需要把功能组件化时维护一个清楚的补丁或上游贡献；向作者发消息或提交 PR 应另按用户授权执行。

此路线也不能承诺只改提示词就完成：用户所要求的浏览历史、多人并行和工具调度仍需真实代码与验收。保留自研是维护成本取舍，不是对自研效果更好的预设。

## 7. 明确的采用/停止条件

| 采用 ContextAware 的必要条件 | 转路线 B 的停止条件 |
| --- | --- |
| 复用其图片回看、预处理和来源接口，确实能退役本地重复选择逻辑 | 仍需要两套缓存/选择器长期互相兜底，或必须重写其 ImageIndex / SessionManager |
| 一个独立兼容层即可完成桥接，最多为会话键和事实型场景输出增加窄扩展点 | 必须改 AstrBot 核心、改多个第三方插件内部流程，或升级要人工修补大量私有方法 |
| User Policy 原隔离、访问范围、清理信号与成员权限均通过 | 靠关闭隔离、放开路径、绕过权限/额度或扩大范围才能运行 |
| 当前模型在完整连续场景中能自主查找并选择资料 | 只能靠“三视图专用规则”、手动填写正确图片 ID 或不断追加案例关键词才能通过 |
| 原有重要能力保留，保留/恢复策略可解释且可验收 | 不说明就丢掉重启恢复、文档、人格切换、开工对白或失败保护 |
| 日常路径无新增串行总结/图像描述调用，普通本地准备耗时达标 | 为了接入，每次聊天固定多跑一遍摘要/识图/重复判断，或引入持续排队 |

不能只凭新增代码行数决定复杂度；要记录修改上游的扩展点、私有接口数量、保留的重复模块、升级操作及验收负担。若两个关键接缝无法以窄接口解决，就不继续扩大验证范围。

## 8. 验证顺序与场景

### 阶段 0：冻结与备份

固定候选提交、现有本地 Git 版本和部署配置。仅在独立容器/进程使用临时数据目录，替代 QQ 发送器和图片生成器；不得让影子实例连接真实 OneBot WebSocket。复制合成配置，不复制 QQ 登录态、真实记忆或聊天图片。此阶段不切换生产插件。

### 阶段 1：先验证接缝，限制投入

先做 A1 隔离和 A3 图片桥接的原生 runner 替身测试，再做 A2 事实型场景注入。核对最终序列化给 Provider 的真实 schema 是否包含完整来源参数、权限包装后是否保留；参数在执行前有没有被过滤，不能只看 Python 对象里有字段。若触及停止条件，即结束整套接入，转 B，不先把插件装进生产继续打补丁。

### 阶段 2：同样材料对照 A 与 B

以下每类先用替身验证机械正确性，再选择关键场景通过现有两条真实模型路由做少量合成测试。真实模型初验按总请求数限额（含工具往返），建议首批上限 40 次；不能无限重试刷通过。该额度是后续实施建议，本轮未执行任何调用。

| 场景组 | 验证内容 |
| --- | --- |
| 连续多图 | 单独正面图 → 首版结果 → 补侧面图；模型自行回看、选择并交付完整必要参考 |
| 跨成员引用 | B 加入 A 的讨论，并要求采用 C 较早图片中的元素；不要求复述全部指令 |
| 替换与新话题 | 明确不用旧图、独立新角色、仅讨论能力、引用歧义；不把所有旧图一律带上 |
| 多人互动 | A 请求改文案，B 另问代码，C 补充 A 的条件；分别响应、不丢请求、不混身份 |
| 意见冲突 | 第二个人否定第一人的目标，模型区分意见与授权、必要时澄清，不默认后者覆盖 |
| 沉默与问候 | 群友互聊可沉默；叫名字、空 @、回答 AI 问题可以自然回应，无需具体任务词 |
| 工具与并发 | 生图等待期间文字互动、迟到结果、失败、取消和重复消息；实际输入与任务对应 |
| 隔离与恢复 | 群/私聊/人格/成员策略、reset/new、重载和缓存淘汰；越界拒绝且不改成无参考生成 |
| 文档与长期资料 | 翻找空文字图片消息、读取较早文档、核对出处，保留旧文字和长期记忆能力 |

权限、来源、计次、发送与重复执行等机械检查必须全部通过。主模型连续任务在两条路由都要通过代表性样本；保留失败样本与原因，不能宣称小样本通过就保证语义永不出错。

### 阶段 3：一次只灰度一套

通过后仅在测试群迁移，保存可以恢复的职责开关表。用户发起实际聊天，观察真实收发与多图一致性；不自动重放刚才的真实角色图。每次仅让一套接话/选图流程负责处理，同一消息只允许一次对应的实际执行。文档和历史数据保留，旧代码先停用后再考虑删除。

## 9. 时延、成本与回滚

对照时保持相同模型、参数、素材和历史量，分别记录入队等待、判断、上下文准备、首次模型返回、资料回看、工具调用、续答及发送。不能把所有总耗时归到模型，也不能只看工具已开始而忽略前置排队。

普通本地准备新增 p95 目标不超过 200 ms，同一数据卷至少 40 条合成样本。普通路径不增加串行摘要/图像转述，不重复跑两套接话判断。真实模型样本少时报告逐次耗时、调用数和输入量，不据此承诺稳定 p95。复杂回看必要的模型往返单独列明。

失败时按备份恢复原有插件开关、上下文与图片转述配置，暂停兼容层并重载已固定版本；不清空聊天历史或长期记忆。隔离验证没有生产数据，灰度新产生的允许消息与素材按原保留期保存，不以“回滚”为由删除用户资料。

**本次交付为选型与实施方案。下一步应执行阶段 0/1 的有界验证，根据实际适配与场景结果选择 A 或 B，而不是先假定必须采用 ContextAware 或必须自研。**

## 10. 本地 / ContextAware 切换设计

结论：可以做成可回退的后端选择，但需要先拆清职责，不能仅在界面增加两个独立启用按钮。当前存储、附件读取、文档、日志已有独立模块，主要耦合在 main.py 的事件钩子、router 上的策略/状态访问、业镜去重和万象画卷的结果回写；不需要因此重写全部工程。

### 入口与配置

后台提供一个“上下文方案”单选项：`builtin`（本地实现）或 `contextaware`（适配实现）。初期以现有测试群为范围，全局默认加群级覆盖作为后续扩展。ContextAware 未安装或适配验证未通过时，该选项显示不可用及原因，不能表面切换成功、实际默默运行本地实现。

人格模型、User Policy 权限、文档/旧文字索引、长期记忆、表情包及万象画卷继续作为共用能力。历史读取、文档等已有功能开关保留；“是否关注消息”的模型判断另按本方案规定由唯一负责人执行，不能把 ContextAware 本身当作完整主动回复引擎。

初期只提供经过整体验证的两个配置组合，不开放任意拼接“本地选图＋ContextAware 选图＋两套判断器”的自由组合。不同方案可以使用同一主模型，因此模式切换不自动改变人格、模型或推理参数。

### 模块边界

| 模块 | 切换时的处理 |
| --- | --- |
| 策略与身份 | 共用；抽出范围检查接口，不再借由某个接话 router 才能取得授权范围 |
| 消息与文档持久层 | 共用既有数据，关闭方案不删除记录；存储格式独立于选图策略 |
| 近期上下文与历史图片读取 | 后端接口负责登记、准备请求、暴露资料和解析图片 ID；每个事件只有一个选定后端 |
| 接话与去重 | 独立职责；使用选定模式的判断结果衔接业镜，不能复用残留事件标记误拦新模式 |
| 图片执行与结果回写 | 共用执行桥；素材按发起时的后端解析，成功结果回到原请求对应后端 |
| 日志 | 共用；额外记录后端、配置代次、模型、来源 ID 和耗时，便于模式对照 |

后端接口是对两套实现的薄封装，至少覆盖事件登记、请求准备、工具可见性、素材解析、清理和生命周期管理。不能为了统一接口，把 ContextAware 的缓存和场景实现再复制一次。

### 切换的执行边界

1. **真正互斥。** 未选中的后端不注入提示、附图、发起判断或执行发送。尤其 ContextAware 有自己的消息/LLM 钩子；只让本地代码提前 return 不会阻止其运行。须先验证原生配置/插件范围能否可靠隔离，必要时用有边界的适配入口。无法隔离则先用独立实例或停用/重载切换，不宣称已经支持同实例热切换。
2. **请求固定归属。** 入站事件记录后端和配置代次。在途图片任务保持原素材快照与回执，不能因用户换开关就换图、重复执行或把结果记入另一个目录。
3. **首版采用空闲切换。** 有在途推理/工具任务时显示等待或拒绝本次切换，不取消任务。切换事务短暂阻止新任务派发并保留待处理消息，更新配置、钩子和工具后再放行。若确实需要重载，明确显示；当前不能承诺零等待热切换。
4. **保留历史但不伪装兼容。** 两套缓存 ID 不天然互通；需通过统一来源映射或已验证恢复路径读取旧素材。暂不能迁移的条目说明不可用，不把“数据还在磁盘”当作新后端已经能够读取，也不自动清空历史来掩盖问题。
5. **依赖失败可见。** 候选后端不可用时报告故障并保留当前有效配置，允许明确切回本地。后续若引入自动降级，应单独展示实际后端，不能在对照测试中隐藏回退。

切换本身是本地配置与路由选择，不需要新增模型调用；不能据此承诺两个后端的回复耗时相同。初期不采用影子双执行，不会为了比较而把每条真实消息调用两遍模型或生成两张图片。

### 额外验收

- 单次切换后，同一消息只被一套上下文/选图流程处理，图片只执行和发送一次。
- 本地 → ContextAware → 本地往返，模型、人格、访问范围和共用历史保持正确。
- 在途任务、切换瞬间到达的新消息、切换失败恢复、清理命令与插件重载均不丢请求、不串素材。
- 原后端停用后，无残留钩子、工具暴露、去重标记或结果回写影响新后端。
- 任一后端未经适配验收时，不在界面显示为可投入运行的选项。

此节为设计补充，尚未开发或上线切换界面。它不改变前述复杂度停止线：若实现可靠互斥需要重写第三方内部流程，应保留独立实例对照或转路线 B，而不是为了一个开关长期维护更大的分叉。

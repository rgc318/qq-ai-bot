# 图片任务一致性优化方案

实现版本：1.10.0。上线结果以 `STATUS.md` 最新段落为准。

目标：保留模型自主理解、多人/多图来源选择和独立新图能力，避免“声称沿用原图、实际空参考生成”。正常成功路径不增加模型请求、摘要或固定等待。

## 已确认原因

21:44 的请求第一次漏填参考集合，被拦截后补成空数组并按新图执行；21:48 用户纠正后，模型读取既有生成消息并选择三视图，实际传入一张参考。档案并未丢失。当前只有参数/权限校验，缺少明确的任务语义契约、重试期间的一致性与发送时机约束。

## 实施范围

1. **来源表达**：共用图片目录保留来源消息、生成/上传类型、原始生成请求的短摘录、父图关系和顺序。摘录只是事实资料，不自动判定任务，不建立三视图/玩偶等场景规则；不另调视觉描述模型。
2. **同次调用的任务声明**：图片工具明确给出 `image_task`，包括 `operation`（independent / edit / reference）、选择理由；独立新图还需引用当前用户允许独立创作的原话。沿用已有图修改或参考创作必须非空 `reference_ids`，逐图 `reference_notes` 说明用途；信息不足应先读取来源或澄清。
3. **执行校验**：检查结构、有效来源、任务类型/参考集合的一致性。声明 edit/reference 后，同轮修正不能偷偷降级 independent；允许真正的新图带空集合，不自动套用最近图片。所有辅助参数在万象画卷执行前移除。
4. **有限纠错**：无效调用只给一次修正机会，仍不完整或矛盾则移除本轮图片工具，明确说明没有启动生成；不触发付费图片请求、不无限循环。沿用既有权限、额度和不可重试的上游失败处理。
5. **开工对白**：当前两条聊天路线为非流式；若模型把简短开工文字放在同次图片调用的普通正文里，将其移到 `pending_message`，在参数/参考校验通过后再发出。复用模型原话，减少额外短模型调用和先承诺后校验。混合其他工具、普通文字和流式回复保持原输出路径。
6. **可观测性**：记录任务类型、校验结果/错误码、参考数量、修正次数、对白来源和本地耗时，不记录完整提示词/图片/凭据。

## 验收与部署

- 覆盖改图空参考、有效多图、跨成员来源、独立新图、含图但明确独立创作、歧义/缺图、伪造/越权 ID、同轮降级、重复无效调用、辅助参数剥离、原生权限代理、发送前校验和成功路径。
- 使用真实 AstrBot SDK 和禁网隔离容器，不重放真人照片或真实聊天，不实际生图/发 QQ。已有存储、后端切换、模型绑定、记忆、表情和工具回归保持通过。
- 仅用虚构文字和来源目录对 DeepSeek/Sol 进行工具选择对照，不执行工具；记录次数、耗时和参数合规，不能把数据链正确等同于模型永不误判。
- 在相同数据卷的独立空目录测量新增校验及普通文字准备开销；普通成功路径不额外调模型。只灰度测试群，空闲部署、备份、检查失败回滚。

## 能力边界

结构化声明能减少和阻止已表达意图与执行的矛盾，不能凭代码证明自然语言语义完全正确。若模型仍错误声明 independent 并提供似是而非理由，仍可能误生成；必须通过合成语义测试和真实使用持续核对，不能声称本地校验已具备独立语义理解。缺参只阻止执行，不由程序猜图或伪造模型参数。暂不增加全量第二模型审核，避免每次生图多一次串行等待。

## 实现与验收记录

- `image_task_contract.py` 负责纯结构/一致性验证；`image_response_adapter.py` 在当前非流式、纯图片工具响应时暂存开工文字。原生权限代理和万象画卷正常调用路径保留。
- `image_task` 与用途参数均在执行前消费，底层工具不接收不认识的辅助字段。校验状态绑定本轮事件，沿用原有结束清理；新请求不会继承失败计数或已声明的旧任务类型。
- 来源摘录从原消息/生成任务请求直接取得，每张最多 96 字符、总共最多 640 字符，不通过另一个模型生成摘要。引用内容仅是资料，不覆盖系统规则。
- 22 项纯任务/响应检查、71 项原生上下文及图片执行检查、22 项存储和 10 项执行守卫回归通过。原生测试使用实际 Provider 的纯文字 MessageChain 格式，确认：首次空参考 edit 的处理器执行次数为 0；修正后只执行一次且收到选中原图的真实字节；开工对白只在成功校验后发送一次；连续两次无效调用后，实际下一轮 Provider 工具集合不再包含生图工具。富媒体内容保持原路径。已确认发送成功的任务会释放其纠错锁，允许同一请求继续执行用户另外要求的独立新图；失败/尚未确认的改图不能借此降级。
- 在同一 Docker 数据卷的独立临时子目录、约 30.1 MB 合成素材、各 40 条普通文字样本下，最终本地后端 p95 7.053 ms，ContextAware p95 10.676 ms；ContextAware 首次恢复 44.270 ms。上一版同类测量为 p95 8.057 ms、首次 43.738 ms，两次测量不是严格配对，不能把差值当生产平均增量。10,000 次纯任务校验 p95 约 0.0011 ms。
- DeepSeek 1017 与 Sol low 的“旧三视图改材质、跨成员组合、忽略旧图的独立新图、真正歧义”共 8 个规范场景全部通过，合计 12 次纯文本接口调用、0 次参数校验返工。改图/组合各用了两次模型调用（先查来源，再选择参考）；独立新图与澄清各一次。这是必要资料回看的示例，不代表所有生图只有一次模型调用，也不是生产时延基准。
- 首轮测试夹具遗漏了已有生产「图片任务执行」规则，DeepSeek 独立新图只回文字，首轮 7/8；补齐与生产一致的规则后重新完整运行，8/8。两轮报告均保留在忽略的日志目录，共 24 次文本调用。未重放真实会话/图片、调用图片接口或发 QQ。

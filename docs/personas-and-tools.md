## 如何聊天与切换

当前空 @ 会进入原生正文流程，由模型结合近期记录承接或自然回应；不再仅限于下方旧版的“补接上一条文字”规则。近期事实包含多成员、引用关系与预算内图片，较早资料仍需按需回看。

本地插件 1.7.0 新增连续对话关系：同一用户已明确向 AI 发言，之后没有其他成员插话或转向别人时，默认保留 10 分钟空闲窗口。“你是谁”“那你现在用哪个模型”“还在吗”等明确短句可直接进入正常回复；其他表达带关系证据交给 Qwen 判断。开工对白、图片发送状态补入近期记录，窗口按同一对话的助手活动更新；不增加模型调用，也不保证主模型立即完成。群友插话、点名别人、转述和要求沉默仍受避让规则约束。开关位于本地插件配置 → 语境追问快速回复 → `dialogue_continuity_enabled`，空闲时间为 `dialogue_continuity_window_seconds`（默认 600，最多 1800）。详见 [连续对话衔接](dialogue-continuity-2026-10-24.md)。

2026-10-23 已补充语义追问路径：跨成员的“给我也整一份”、改图和继续追问可绕过普通接话的静默与冷却。完整场景、时效和验证见 [回复条件](reply-conditions.md)。

- @ 机器人或引用机器人消息，可正常唤醒。
- 消息以“大肥鱼”“肥鱼”“龙娘”“ai助手”“AI助手”开头也能唤醒；这些称呼只负责唤醒，不单独改变当前人格。
- 明确唤醒和已成立的连续对话可直接进入正文；其他适用消息由本地语义判断器结合近期记录决定是否接话。已判断过的消息不会再交业镜重复判断。业镜保留尚未判断消息的主动调度，静默 / 冷却不是每条回复的固定等待。当前统一入口见[架构说明](shared-context-architecture-2026-11-01.md)，旧版规则演变见 [reply-conditions.md](reply-conditions.md)。
- 当前原生群白名单包含 347440128、476547826；本地插件和业镜范围分别配置。后台巡检保持关闭，原生概率回复不作为另一条并行接话路径。

### 选择每个人格使用的聊天模型（1.11.5）

进入 **插件 → QQ 人格模型与回复条件 → 配置 → 人格与聊天模型绑定**。展开已有的“人格模型绑定”条目，或点击“添加条目”；“人格”从已有人格列表选择，“聊天模型”从 AstrBot 已配置的聊天模型中选择，最后保存插件配置。新模型需先在“模型提供商”中添加并启用；不是直接列出 LiteLLM 所有尚未配置的远端模型。生图节点仍由万象画卷单独配置。

升级前已打开的旧“修改键值对”窗口应取消，刷新页面后重新打开插件配置，以免提交旧页面的过时内容。旧 `bindings` 字典在加载时自动迁移为原生 `template_list`，逐项保留实际人格 ID 和 Provider ID；不把自定义值替换为示例默认值。每个人格保留一条，重复时最后一条完整绑定生效，未填完整的条目忽略。删除绑定后，该人格恢复 AstrBot 原有的模型选择规则。

运行时普通聊天、延迟接话、生图前对白与读图能力检查都读取同一绑定。迁移只在加载时写入配置，不增加模型请求或固定等待。升级脚本为 `scripts/deploy-persona-selector.py`，从 1.11.4 空闲升级并备份原文件及配置，失败自动回退。回退到旧版插件时，必须同时恢复迁移前的字典配置；不要只替换源码。

“QQ 人格模型绑定”在模型选择之前，将人格映射到 Provider。它同时覆盖普通请求与业镜延迟接话，不修改社区插件源码。源码与配置定义位于 `extensions/astrbot_plugin_qq_persona_models/`，安装副本存于 AstrBot 数据卷。多人格管理保留的单条规则 Provider 应留空，避免出现与人格映射相反的显示。

切换群人格的权限应核对平台识别的群主/群管理员、AstrBot 管理员，以及该群的策略管理员设置。添加“成员个人设置”不等于增加策略管理员；机器人自身账号也不应当作人的管理账号填写。后台群 ID 和指令侧的会话范围需一致，具体排障见[群人格权限故障记录](group-permission-incident-2026-10-24.md)。

## 添加新群

先让机器人 QQ 加入目标群，然后逐项保存以下配置；只在业镜填群号不足以开放整条链路。

1. **配置文件 → 访问控制**：将新群号加入该机器人实际使用配置的群白名单，保留原群；管理员默认不能绕过群白名单。
2. **插件 → QQ 人格模型与回复条件 → 配置 → 回复条件 → 生效群号**（`reply_conditions.allowed_groups`）：加入新群号，开放本地路由、上下文及人格模型适配范围。
3. **业镜 → 配置 / 页面**：若需要普通群聊主动接话，在其生效群范围中加入新群；只需要 @ 聊天时不必额外开放主动接话。
4. **多人格管理 → 群聊管理**：导入已有会话或添加对应群，选择默认人格。共享群 ID 应对应真实群号，不把“成员号_群号”的旧个人会话误当共享群。
5. 如需长期记忆或图片工具，另核对 LivingMemory、万象画卷的群白名单、配额和成员权限；查看后台群策略是否禁用了相应插件。

先用自己真实发出的 @ 文本和图片请求验证，并查看日志中的群号、有效人格、Provider 与来源 ID。不通过时核查各层范围，不靠关闭全部权限检查来排障。后台保存原生配置才生效，仅改 `config/deployment.local.json` 不会自动应用。

## 分段、上下文和耗时开关

- 分段回复：配置文件 → 扩展功能 → 分段回复。当前随机间隔 0.3–0.8 秒、阈值 150；超过阈值的长回复按原生实现可能整条发送，不是工具出错。
- 首段立即发送：本地插件 → 配置 → 分段回复发送。仅去掉首段人为停顿，不在模型尚未生成完成时输出，见[发送说明](first-segment-delivery-2026-11-02.md)。
- 历史预览：本地插件 → 统一消息与附件上下文 → 自动附图 / 统一近期输入。当前最多 16 条 / 6000 字符、4 图 / 1024 像素 / 1 MiB。
- 较早资料：同一区域的按需回看开关；旧对话文字索引另见[历史检索](history-recall.md)。关闭自动附图可能反而需要更多读图工具轮次。
- 完成检查：本地插件 → 资料可见状态与任务完成检查。只对明确证据矛盾最多纠正一次，关闭后保留上下文和原图，见[证据说明](task-evidence-and-correction-2026-11-01.md)。
- 后端切换：本地插件 → 上下文后端页面，等待在途任务结束再切换。当前使用受管 ContextAware，两个后端共用近期事实与附件档案。

### 历史参考图、连续改图与多张输出（1.11.4）

测试群当前启用 ContextAware 后端，共用持久化消息与附件档案。图片存在、未过期且仍属当前群/人格的允许范围时，不必每轮重发；模型可按当前目录或历史工具找回原图，并明确选择参考集合及用途。重载/切换后，归档来源编号保持稳定。若旧编号无效，应先查目录重新定位；真正缺失、过期或不在当前范围时才说明原因。入口和边界见[上下文运行层](context-runtime-2026-10-25.md)及[历史图片编号记录](historical-reference-id-incident-2026-10-26.md)。

```text
用前面的人物照片和玩偶图再合成一张，这次人物骑在玩偶上。
以上一张生成图为底稿，只改变动作，其他画面细节尽量保留。
基于这张角色图，分别画开心、生气、惊讶、困倦四张独立图，每张单独发。
```

前两个例子分别表达“利用原始资料重新创作”和“编辑已有结果”，应说清需要保留哪个底稿。模型负责选择，不会机械固定为最新一张或最新两张图片；存在无法消除的歧义时会询问。

自然语言请求一轮最多成功交付 4 张独立图片，支持同主题变体或逐张不同描述；同一批共用参考集合。部分失败保留成功图并报告失败编号，不整批重复生成。每日额度、上游限速和权限仍生效，张数增加也会增加时间与费用。详见[多图方案](multi-image-plan-2026-10-26.md)。

2026-10-26 两轮真实群聊已完成历史双图恢复、改图接口、QQ 投递、归档和文字收尾，最新一轮无参数重试或重复生图。1.11.4 同时兼容模型误用的 prompt/action 描述字段。图片生成前的开工对白仍由当前人格模型创作，校验通过后发送。调用成功不等于已自动看图验收，收尾不应把未经核验的画面细节当成事实。真实耗时及这项限制见[流程复核](runtime-latency-review-2026-10-26.md)。

万象画卷包含两组形象描述，可在它自己的配置页选择用于 `/自拍` 的人设；尚未提供参考图，因此没有承诺自拍一致性，也没有把生图插件的自拍人设选择与聊天人格冒充为自动联动。普通自然语言生图使用当前聊天人格提供的描述。

读图：历史指定模型通过过合成视觉测试，但不代表后来选择的所有 Provider 均重新验收。当前两个正文入口统一提供预算内最多 4 张历史预览；更早图片和高清细节按需读取。判断器只接收文字事实和附件元数据，不进行额外视觉模型调用。

计算机运行环境为 `none`，定时任务工具及语音未启用。2026-10-23 已新增 LivingMemory 与 Embedding 提供商，启用记忆回忆/写入工具和人格隔离；表情包管理器已按人格分别绑定 15 张大肥鱼、19 张通用精选图。用法、后台入口与验证见 [长期记忆和表情包](memory-and-memes.md)。原生 `send_message_to_user` 因 OneBot 平台支持主动发送而显示启用，之前“跨会话发送已关闭”的描述不准确。工具面板的 `active=true` 表示已注册，不能一概视为本次请求实际获授权限；应同时查看配置启用条件及工具自身的权限检查。

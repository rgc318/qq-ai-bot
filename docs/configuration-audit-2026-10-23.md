# 当前配置审计与社区功能对照

检查日期：2026-10-23（Asia/Shanghai）。范围：正在运行的 AstrBot/SnowLuma、原生 API、社区插件实时 API、脱敏错误日志、插件作者主分支文档和模型接口。检查过程中未向 QQ 群发送消息。

后续进展：用户已授权并完成长期记忆与表情包安装，相关“尚未安装”内容是本次审计时的基线记录。当前状态与已完成验证见 [长期记忆和表情包](memory-and-memes.md)。

## 结论

现有组合能够承担单群的多人格聊天、跨成员语境追问、普通主动插话、搜索、读图、生图及单张参考图编辑。当前优先事项是理顺工具和模型的控制入口、补齐运行维护与多轮图片关联；不需要立即堆叠多个主动回复插件。

这是一组社区功能的针对性对照，并非全社区配置调查或流行度排名。

## 已完成的修复和验证

1. **AnySearch 普通搜索失败**：近期日志存在两次 `Invalid tag: general` / HTTP 400。原生工具说明要求普通搜索不传 tag，但模型可能传入 general。本地插件 1.1.1 在调用前删除这一特定参数，保留垂直标签与其他工具参数。实际搜索返回 AstrBot 官网与文档；同时检查了垂直分类保留和不影响其他工具。
2. **本地诊断接口报 500**：测试替身缺少业镜的 `_gate`，属于诊断实现缺陷，不能据此判断真实聊天已经故障。改为使用独立的真实 SessionGate。五项回调验证全部通过：任务记录、已发回复记录、跨成员唤醒、业镜去重、引用前文注入。
3. **图片编辑已验证**：通过实际万象画卷接口提交一张合成参考图，使用 `gpt-image-2.5`、单张低画质，将红方块改绿并保留蓝圆。19.16 秒返回成功，输出经目视确认；不是仅检查插件声称支持。结果在 `logs/image-editing-test.png`。
4. **文档纠正**：人格工具实际为 null，不是仅两项；原生跨会话发送工具按平台能力启用，不应描述为一律关闭。保留用户当前人格内容与工具选择。

本地插件旧文件保存在 `backups/before-audit-1.1.1/`。修改仅涉及本地插件的兼容钩子和诊断代码，没有改社区插件或官方镜像源码。

- 两个容器均 healthy，运行约四小时。单次采样：AstrBot 约 347 MiB，SnowLuma/QQ 约 1.15 GiB；不是全天稳定性测量。
- 三个社区插件启用正常，当前安装版本与检查时作者 main 分支 metadata 一致：业镜 1.5.1、多人格管理 v3.5.6、万象画卷 3.3.23。
- 群 347440128 使用共享群上下文、大肥鱼默认；人格与模型绑定检查通过。龙娘使用 Responses / low。
- 业镜实时接口和原生配置的关键等待参数一致：10 秒延迟、10 秒静默、60 秒冷却，判断模型 qq-reply-judge-fast；不是叠加等待 20 秒。
- 快速语境通道 180 秒窗口，置信度阈值 0.88，判断超时 10 秒。置信度未做概率校准。
- 人格提示词已有简短闲聊约定：大肥鱼通常一到三句，龙娘闲聊简短。正式回复输出上限 4096 tokens，普通主动插话 500 字符。
- 原生上下文压缩已开启：llm_compress、max_turns=-1、keep_recent_ratio=0.15，未知模型窗口兜底 128000。不能误报为未配置压缩。
- 图片上限为每人每日 10 张；缓存容量限制 512 MB，未启用定时清空。容量限制已能限制增长，不必为此盲目清空图片。
- 管理端口只开放本机回环，镜像锁定摘要，数据使用命名卷，日志有轮转。
- SnowLuma 错误中可见 Linux 桌面通知服务缺失；这是 QQ 桌面弹窗的 DBus 通知问题，未据此发现 OneBot 断线，不能等同于消息桥接失败。

## 优化事项及优先级

| 优先级 | 实际发现 | 建议与当前处理 |
| --- | --- | --- |
| 高 | 管理员 QQ 2354912009 就是机器人自己 | 提供真实操作者 QQ 后再设 AstrBot 管理员。群主/群管理员仍能使用多人格管理支持的群切换命令。未猜测或擅自提升群成员权限。 |
| 高 | 两个人格 tools=null，继承所有插件工具；未配置的视频工具也在其中 | 在人格设定显式选择生图、搜索及确实需要的自拍；再单独审视原生内置工具。人格工具表不能被当作所有内置能力的唯一开关。本次未覆盖用户选择。 |
| 高 | 本地人格映射覆盖群规则中的回复模型 | 保持“群规则选人格、映射选模型”这一种管理方式；如需不同群的同一人格使用不同模型，改成群优先的映射，或复制人格 ID。不要以为群里选模型必然胜出。 |
| 中 | 原生 fallback 列表含主模型自身以及旧 DeepSeek Flash | 自身重复项没有必要；主模型失败时可能回退到非指定版本。若要求人格模型严格不漂移，去掉旧回退并保留重试；若重可用性，明确列出允许的替代模型。本次保留原策略。 |
| 中 | 自定义模型 max_context_tokens 未显式设置，依赖识别或兜底 | 按上游真实窗口填写。LiteLLM /model/info 对当前虚拟 Key 返回 403，不能凭模型别名猜测准确窗口。128000 是兜底，不是已验证的实际模型规格。 |
| 中 | 改图接口可用，但没有验证自动跟踪上一张生成图 | 现阶段引用图片或图文同发；完善按群/任务保存图像引用、多图时澄清目标、过期回退，才接近连续对话改图体验。 |
| 中 | 自拍形象没有参考图，激活自拍人设仍为 whale | 提供两个人格的参考图，并把聊天人格与自拍选图按请求关联；不要直接切换一个全局自拍开关，避免不同群互相影响。 |
| 中 | 普通插话 10 秒/60 秒/每日 100 次比作者建议更积极 | 保留满足当前用户诉求；繁忙群可试 15–20 秒/120 秒/每日 30–50 次，语境追问继续即时判断。不要为了安静而让明确请求也等待。 |
| 中 | 只有部署/变更快照，没有建立可验证的完整恢复流程；未配置 Windows 启动 WSL/Docker | 制作数据库、原生配置、插件和 QQ 登录状态的受保护备份，并做一次恢复演练。restart:unless-stopped 不等于 Windows 开机自启。不在本次审计内创建定时任务。 |
| 低 | 旧成员会话形式群规则仍保留 | 旧规则是默认人格，当前共享群规则正常。可在备份后清理以减少管理界面混淆；本次未删除。 |

## 社区功能对照和选择

| 功能 | 社区方案 | 我们的状态与建议 |
| --- | --- | --- |
| 自然接话 | 业镜：静默后判断、冷却、白名单、主 Agent 工具继承 | 已有；另有本地跨成员追问快速通道。无需再安装第二个同类插件。 |
| 多人格、多群路由 | 多人格管理：固定/自动人格、成员规则、模型、历史隔离、计划 | 已有固定人格与切换。自动人格会多一次选择请求，现阶段先保留手动切换；计划不会自动发言。 |
| 搜索 | AstrBot 原生 AnySearch | 已有并修复 general 参数。匿名额度仍由服务商决定，使用强度上升后再接正式搜索 Key。 |
| 文生图、图生图 | 万象画卷：参考图、改图、自拍、多节点链路 | 已有并验证单张改图。优先补多轮图片引用和角色参考图，而非再装一个重复生图插件。 |
| 长期记忆 | LivingMemory 2.7.1：总结、混合检索、图谱、人格隔离、管理页 | 尚无长期记忆。LiteLLM 列有 Qwen3 Embedding / Reranker，但还没创建原生提供商或实测向量接口。是下一项值得试点的新增能力；先只对测试群启用并验证人物归属、人格隔离、删改与召回。历史压缩不能替代长期记忆。 |
| 表情包 | Meme Manager：按会话/人格选包，分类或语义发送，可选自动收集 | 尚未安装。可选的陪伴体验增强，优先使用人工维护的小型分类包；语义检索和自动收集无需一开始就开启。 |
| 语音 | AstrBot 原生 STT / TTS | 均未启用；API 列有 TTS 模型名称，但这不证明 /audio/speech 或音色参数兼容。需要时单独验证，不为文字群默认启用。 |
| 知识库 | AstrBot 原生知识库/检索 | 尚未建立。适合固定群规、项目资料；只有明确资料需求时再做，与人物长期记忆分开。 |

## 建议实施顺序

1. 明确真实管理员，理顺工具清单与模型优先级，完成受保护备份与恢复验证。
2. 补群内图片引用和连续改图、两个人格参考图；这是当前已经提出的体验需求。
3. 若希望跨天记住群友偏好，再小范围部署 LivingMemory，并测试多用户归属和人格隔离。
4. 最后按使用情况增加表情包或语音；继续保留单一主动接话系统。
